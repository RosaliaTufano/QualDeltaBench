Your task is to compare two implementations of the same target function and decide which one is better than the other with respect to code quality.

You will be given:

1. A list of quality aspects to assess, each with a description.
2. The signature of the target function to compare.
3. File A, containing Implementation A of the target function.
4. File B, containing Implementation B of the target function.

Your goal is to decide which implementation of the target function is better with respect to the listed quality aspects.

The files may contain other code and may include changes outside the target function. Use the rest of each file only as context for understanding the target function.

Do not judge unrelated changes outside the target function. Do not reward or penalize either implementation because of file-level differences unless those differences directly affect the target function with respect to the listed quality aspects.

Do not assume that every listed quality aspect is relevant. Select only the quality aspects that represent the clearest and most meaningful quality difference between the two implementations.

If multiple quality issues are relevant, choose the one or ones that are most important for judging the difference between the implementations. Do not list every possible minor issue.

Assume both implementations are intended to implement the same functional behavior.

Use the following decision labels:

- A: if Implementation A of the target function is clearly better with respect to one or more of the considered quality aspects.
- B: if Implementation B of the target function is clearly better with respect to one or more of the considered quality aspects.

Your answer must include:

1. Quality aspects: the selected quality aspects from the provided list.
2. Decision: one of A or B.
3. Key evidence: the specific differences between the two implementations of the target function that support the decision.

Do not reward or penalize differences that are unrelated to code quality or unrelated to the target function. Do not introduce quality aspects that are not in the provided list.

Input:

- Comprehensibility & Readability: comprehensible, understandable, clear purpose, clarity, simplify code, unusual syntax, unusual use of language features, readable, no useless code, brevity/ conciseness, formatting/ layout, style, indentation, adherence to naming conventions, code standard, usage of whitespace, use of idioms, consistency.
- Correctness: runnable/ free of bugs, language/ model/ framework choice, functionally correct, exception handling, robustness.
- Performance: good performance, good use of time and resources, optimize code.
- Maintainability & Code Structure: maintainable, adaptable, reusable, used by others, interoperable, portable, not hardcoding variables and input, global variables, using standard libraries/ functions, use config files, flexibility, well structured, modular, cohesion, low coupling, no duplication, decomposition, structural complexity, encapsulation, grouping, elegance, doing one thing, using clear, consistent, and meaningful logging.
