Your task is to inspect one implementation of a target function inside a file and decide whether it has a code quality issue.

You will be given:

1. A list of quality aspects to assess, each with a description.
2. The signature of the target function to inspect.
3. A file containing the implementation of the target function.

Your goal is to decide whether the implementation of the target function contains an issue with respect to one or more of the listed quality aspects.

The file may contain other code. Use the rest of the file only as context for understanding the target function.

Do not judge unrelated code outside the target function. Do not report issues outside the target function unless they directly affect the target function with respect to the listed quality aspects.

Do not assume that every listed quality aspect is relevant. Select only the quality aspect or aspects that represent the clearest and most meaningful issue in the target function.

If multiple quality issues are present, choose the one or ones that are most important. Do not list every possible minor issue.

Use the following decision labels:

- Yes: if the implementation of the target function has a meaningful issue with respect to one or more of the listed quality aspects.
- No: if the implementation of the target function does not have a meaningful issue with respect to the listed quality aspects.

Your answer must include:

1. Issue: one of Yes or No.
2. Quality aspects: the selected quality aspects from the provided list if the answer is Yes. If the answer is No, write “None”.
3. Evidence: if the answer is Yes, provide the specific code-level evidence supporting the issue. If the answer is No, write “None”.

Be precise and avoid overclaiming. Do not report speculative, very minor, unrelated, or file-level issues that do not directly affect the target function. Do not introduce quality aspects that are not in the provided list.

Input:

- Comprehensibility & Readability: comprehensible, understandable, clear purpose, clarity, simplify code, unusual syntax, unusual use of language features, readable, no useless code, brevity/ conciseness, formatting/ layout, style, indentation, adherence to naming conventions, code standard, usage of whitespace, use of idioms, consistency.
- Correctness: runnable/ free of bugs, language/ model/ framework choice, functionally correct, exception handling, robustness.
- Performance: good performance, good use of time and resources, optimize code.
- Maintainability & Code Structure: maintainable, adaptable, reusable, used by others, interoperable, portable, not hardcoding variables and input, global variables, using standard libraries/ functions, use config files, flexibility, well structured, modular, cohesion, low coupling, no duplication, decomposition, structural complexity, encapsulation, grouping, elegance, doing one thing, using clear, consistent, and meaningful logging.
